2. EXECUTIVE PROJECT OVERVIEW
====================================================================================================

Grand Horizon is an end-to-end, enterprise-grade Hotel Management & Hospitality Operations platform
engineered using modern MERN stack architecture. It replaces disconnected legacy hospitality tools
with a unified, real-time operating system that connects luxury guest booking experiences with high-
velocity staff flight operations, housekeeping maintenance, and executive-level governance.

Key Pillars of the System:
1. Zero Double-Booking Guarantee: Atomic MongoDB transaction locks preventing race-condition collisions.
2. Dynamic PBAC (Permission-Based Access Control): Granular matrix control down to individual actions.
3. Zero Optimistic UI: All state mutations require server confirmation, preventing corrupted workflows.
4. Production-Hardened Security: JWT rotation, rate limiting, Helmet HTTP headers, audit trails.
5. High-Aesthetic UX: Custom dark-mode Obsidian UI for staff consoles and Verde cream for guests.

3. COMPLETE TECHNOLOGY STACK
====================================================================================================

FRONTEND ARCHITECTURE:
* Framework:           React 18.3 + Vite (Fast ESM Bundler, optimized chunk splitting)
* UI Systems:          Material UI (MUI v5) + Tailwind CSS + Framer Motion animations
* State Stores:        Zustand (Global auth state, draft booking store, UI drawers)
* Data Fetching:       TanStack React Query v5 (Server-state caching, invalidation, mutations)
* Routing:             React Router DOM v6 with dynamic <Can> permission guard wrappers
* Forms & Validation:  React Hook Form + Zod / Joi validation resolvers
* Visual Data:         MUI X-Charts & MUI X-Data-Grid for enterprise data manipulation
* Icons & Assets:      Lucide React Icons + Cloudinary CDN media delivery

BACKEND & INFRASTRUCTURE:
* Runtime:             Node.js (LTS v20) + Express.js 5 (Modular Route-Controller-Service pattern)
* Cloud Platform:      Vercel Serverless Functions (Zero cold-start connection caching)
* Database:            MongoDB Atlas (Cloud M0 Replica Set with transactional session support)
* Object Modeling:     Mongoose v8 (Custom schema statics, virtuals, compound indices)
* Validation Layer:    Joi 18 (Strict input sanitization across query, params, and body)
* Authentication:      JWT (Access Tokens 15m + Refresh Tokens 7d + Secure Cookies)
* Logging:             Winston structured multi-transport logging + Morgan HTTP request streaming
* Payment Processing:  Stripe API (PaymentIntents, Webhook verification, automated refunds)
* Invoicing Engine:    PDFKit (Dynamically generated official PDF receipts and invoices)
* API Documentation:   Swagger UI & OpenAPI 3.0 specification (/api-docs)

====================================================================================================
5. ENTERPRISE ENGINEERING HIGHLIGHTS & ARCHITECTURAL DECISIONS
====================================================================================================

1. Atomicity & Race-Condition Safety:
   - Dual overlapping booking prevention using MongoDB transactional isolation (`session.startTransaction`).
   - Stress-tested against concurrent simultaneous booking requests; 1 succeeds (201 Created), 
     conflicting request safely fails (409 Conflict) with zero double-bookings.

2. Scalable Serverless Backend:
   - Configured via Vercel Serverless with Mongoose readyState connection caching. Eliminates 
     the database connection exhaustion typical in serverless Node.js deployments.

3. Strict PBAC Boundary Enforcement:
   - Permission checks are enforced twice: on the frontend (omitting DOM elements) AND at the 
     backend middleware level (`requirePermission`). Any spoofed API request returns HTTP 403.

4. 100% Quality Assurance Verification:
   - Passed 146 unit & integration tests covering authentication, concurrency, and PBAC security.
   - Comprehensive Playwright end-to-end browser tests verifying all 4 personas on real DOM trees.
