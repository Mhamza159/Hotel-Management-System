<objective>
Implement Plan 05-01: Tiered Cancellations, Authoritative Server-Side Refunds, and Inventory Release
1. Build `src/services/refund.service.js` with zero client-trust logic computing hours remaining before check-in against REFUND_TIERS (100%, 50%, 0%).
2. Enforce User Mandate:
   - Advance payment rule: Refund ONLY calculated if `totalPaid > 0`. If unpaid ($0), booking cancels with `refundAmount: 0`.
   - Pre-check-in rule: Cancellation strictly restricted to BEFORE check-in (`checkInDate > now` and `status !== 'checked-in'`).
3. Build `src/services/cancellation.service.js`:
   - Validates ownership (guest owner, receptionist, super-admin).
   - Aborts if already checked-in, checked-out, or cancelled.
   - Calculates refund amount via `RefundService`.
   - Transitions booking to `status: 'cancelled'`, records `cancellation` metadata.
   - Unlocks rooms from `Room.reservedRanges`.
   - Creates refund audit record in `Payment` (cash) or dispatches Stripe refund (card).
4. Expose `PATCH /api/v1/bookings/:id/cancel` in `src/routes/booking.routes.js`.
5. Implement unit tests `tests/unit/refund.test.js` and integration tests `tests/integration/cancellation.test.js`.
6. Update Postman collection with Cancel Booking endpoint.
</objective>

<tasks>
<task type="auto" id="05-01-T1">
  <name>Build Authoritative Refund Calculation Service</name>
  <description>
    Create `src/services/refund.service.js`:
    - `calculateRefundTier({ checkInDate, totalPaid, currentTime })`:
      - Validates checkInDate.
      - If `totalPaid <= 0`: returns `{ appliedTier: 'no-advance-payment', refundPercentage: 0, refundAmount: 0, message: 'No advance payment made' }`.
      - Computes `hoursUntilCheckIn = (checkInDate - now) / 3600000`.
      - If `hoursUntilCheckIn >= 48`: returns `{ appliedTier: '100%', refundPercentage: 100, refundAmount: totalPaid }`.
      - If `hoursUntilCheckIn >= 24 && hoursUntilCheckIn < 48`: returns `{ appliedTier: '50%', refundPercentage: 50, refundAmount: totalPaid * 0.5 }`.
      - If `hoursUntilCheckIn < 24 && hoursUntilCheckIn >= 0`: returns `{ appliedTier: '0%', refundPercentage: 0, refundAmount: 0 }`.
      - If `hoursUntilCheckIn < 0`: returns `{ appliedTier: 'no-show', refundPercentage: 0, refundAmount: 0 }`.
    Add comprehensive line-by-line bilingual comments.
  </description>
</task>

<task type="auto" id="05-01-T2">
  <name>Build Cancellation Service & Endpoint</name>
  <description>
    Create `src/services/cancellation.service.js`:
    - `cancelBooking({ bookingId, userId, userRole, reason })`:
      1. Finds booking.
      2. Authorization check: `booking.userId.toString() === userId.toString()` OR staff role (`receptionist`, `super-admin`).
      3. State check: Reject if `status === 'checked-in'`, `status === 'checked-out'`, or `status === 'cancelled'`. Must be pre-check-in.
      4. Fetch completed payments to sum `totalPaid`.
      5. Calculate refund tier using `RefundService.calculateRefundTier`.
      6. In transaction:
         - Update `booking.status = 'cancelled'`.
         - Update `booking.cancellation = { cancelledAt: new Date(), cancelledBy: userId, reason, appliedTier, refundAmount }`.
         - Update `booking.paymentStatus`: if refundAmount > 0 and equals totalPaid, 'refunded', else if partial 'partially-refunded'.
         - Remove reservation range from `Room.reservedRanges` for each room in `booking.rooms`.
         - If `refundAmount > 0`: create refund record in `Payment` model with negative amount or refunded status.
      7. Return cancellation receipt.
    Expose in `booking.controller.js` and `PATCH /api/v1/bookings/:id/cancel` in `booking.routes.js`.
  </description>
</task>
