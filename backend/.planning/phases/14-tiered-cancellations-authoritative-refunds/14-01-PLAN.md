<objective>
Execute Phase 14: Tiered Cancellations & Authoritative Refunds:

### Task 1: Guest Cancellation Request Modal (`CancellationRequestModal.jsx`)
- Transparent 3-tier cancellation policy disclosure:
  - Tier 1 (>48h before check-in): 100% refund.
  - Tier 2 (24–48h before check-in): 50% refund.
  - Tier 3 (<24h before check-in): 0% refund (Non-refundable).
- Mandatory reason text input with validation.
- Submits `bookingService.requestCancellation(bookingId, { reason })`.
- Updates UI to display "Cancellation requested — front desk will review".

### Task 2: Front Desk Authoritative Review Dialog (`CancellationReviewDialog.jsx`)
- Fetches authoritative refund evaluation from `deskService.getCancellationReview(bookingId)`.
- Displays:
  - Guest details and stay dates.
  - Timeline & elapsed time (hours until check-in).
  - Financials (Total, Paid, Balance).
  - Authoritative Refund Policy Tier, exact calculated refund amount, and policy explanation verbatim from the backend.
- Actions:
  - "Approve Cancellation" button: triggers `deskService.approveCancellation(bookingId)` which voids booking and frees room inventory.
  - "Reject Request" button: expands/requires mandatory `rejectionReason` before dispatching `deskService.rejectCancellation(bookingId, { rejectionReason })`.

### Task 3: Front Desk Cancellations Queue (`DeskCancellationsPage.jsx`)
- Connects to `deskService.getCancellationRequests()`.
- Dense Material UI table displaying pending requests:
  - Booking Reference, Guest Name, Contact, Reason, Requested At timestamp, Check-in date.
  - "Review & Audit" button triggering `CancellationReviewDialog`.
- Auto-refreshes on approval or rejection.

### Task 4: Routing & Build Verification
- Mount `/desk/cancellations` in `client/src/App.jsx` under `StaffLayout` and `ProtectedRoute`.
- Run production build `npm run build` in `client/`.
</objective>
